# 페르소나 분석 (Persona Analysis)

프로젝트 설명을 입력받아, 그 프로젝트의 실제 사용자가 될 법한 **가상의 페르소나**를 설계하고, 각 페르소나가 프로젝트와 어떻게 맞물리는지 분석한다.

페르소나는 "평균적인 사용자"가 아니라 **의사결정을 돕는 도구**다. 기획자·디자이너·마케터가 "이 기능, 철수는 쓸까?"처럼 구체적인 사람을 떠올려 판단할 수 있어야 의미가 있다. 그래서 인구통계 나열보다 **상황·동기·불편·행동**이 선명해야 한다.

## 입력

사용자가 준 프로젝트 설명(서비스 소개, 아이디어 한 줄, 기획서 등)이 입력이다. 다음 정보가 있으면 더 좋지만 없다고 멈추지 말 것:

- 무엇을 하는 프로젝트인가 (핵심 가치/기능)
- 어떤 문제를 해결하는가
- 플랫폼·가격대·지역 등 제약

핵심(무엇을·누구의 어떤 문제)조차 전혀 알 수 없을 때만 한두 가지를 되묻는다. 그 외에는 합리적인 가정을 세우고, **가정한 내용을 리포트에 명시**한다. (사용자가 빠르게 바로잡을 수 있게 하기 위함)

## 작업 절차

1. **프로젝트 이해**: 핵심 가치, 해결하는 문제, 사용 맥락을 2~3문장으로 요약한다.
2. **세그먼트 도출**: 사용 동기·상황·숙련도가 서로 *의미 있게 다른* **5개 후보 페르소나**를 기본으로 도출한다(사용자가 다른 수를 말하면 그에 따른다). 나이만 다른 복제본은 만들지 않는다. 5개 안에는 핵심 타깃, 보조 타깃, 엣지 케이스, 필요하면 안티 페르소나를 섞는다. 후보는 이름·별명·한 줄 요약·핵심 목표 수준으로 먼저 스케치한다. **B2B**는 구매 결정권자(돈을 내는 사람)·실사용자·현장 입력자처럼 역할이 갈리므로 역할별로 나누고, 카드에 역할 태그(예: 구매 결정권자)를 붙인다. 구매자·판매자처럼 양면 시장이면 "주요 1명"에 얽매이지 말고 양쪽에 각각 핵심 타깃을 둘 수 있다(적합도 상이 2명이어도 된다). 안티 페르소나(방어·배제 대상)는 카드에 "안티 페르소나" 태그를 붙인다. 프로젝트명이 없으면 설명에서 짧은 가칭을 붙이고 가칭이라고 밝힌다.
3. **대표 3개 선정**: 5개 중 프로젝트의 의사결정에 가장 도움이 되는 **대표 페르소나 3개**를 고른다. 단순히 적합도 순이 아니라 (a) 핵심 타깃을 반드시 포함하고, (b) 나머지는 서로 가장 다른 관점(예: 반대편 시장 참여자, 구매 결정권자, 핵심 타깃과 충돌하는 유형)을 대표하도록 고른다. 선정 이유와 탈락한 2개가 어떤 대표에 가깝거나 왜 제외했는지 한 줄씩 밝힌다. 안티 페르소나는 대표 3개 안에 꼭 넣지 않아도 된다. 핵심 타깃 쪽 관점이 더 부족하면 안티 페르소나를 후보로 두고 교차 분석에서 다룬다.
4. **페르소나 작성**: 대표 3개는 아래 템플릿으로 상세히 작성한다. 나머지 2개는 스케치 수준(별명, 한 줄 요약, 핵심 목표, 적합도)만 둔다.
5. **교차 분석**: 5개 전체를 놓고 비교, 우선순위, 기능·메시지 시사점을 정리한다.
6. **결과물 생성**: 마크다운 리포트를 만들고, 요약 카드를 HTML로 시각화한다.

## 페르소나 템플릿

각 페르소나에 다음을 담는다. 구체적일수록 좋다 — "20대 직장인"보다 "입사 2년차, 월말 정산에 매번 야근하는 29세 마케터"가 쓸모 있다.

- **이름 / 한 줄 별명** (예: 김서연 — "시간이 늘 부족한 실무자"). 현실적인 이름과 나이, 직업, 사는 곳
- **배경**: 하루/일상 속 관련 상황 2~3문장
- **목표 (Goals)**: 이 프로젝트로 이루고 싶은 것 2~3개
- **불편·페인포인트**: 현재 대안에서 겪는 문제 2~3개 (구체적 장면으로)
- **행동 특성**: 기기·채널·사용 빈도·기술 숙련도·의사결정 방식
- **기대와 우려**: 기대하는 점 / 도입을 망설이게 하는 점
- **대표 인용구**: 본인이 할 법한 한마디
- **역할 태그** (B2B나 양면 시장일 때): 구매 결정권자 / 실사용자 / 영향력자 / 현장 입력자, 또는 구매자 / 판매자 / 안티 페르소나 등
- **프로젝트 적합도**: 상(핵심 타깃) / 중 / 하 + 이유
- **시사점**: 이 페르소나를 위해 제품·마케팅이 해야 할 일 1~2개

## 품질 기준

- **그럴듯함보다 유용함**: 모든 속성이 판단에 쓰일 수 있어야 한다. 장식용 디테일(혈액형, 취미 나열)은 넣지 않는다.
- **서로 달라야 함**: 페르소나마다 목표와 우려가 충돌하거나 달라서 우선순위 논의가 가능해야 한다.
- **고정관념 주의**: 성별·나이·직업으로 능력이나 성향을 단정하지 않는다. 행동과 상황으로 묘사한다.
- **가상임을 명시**: 실제 조사 데이터가 아니라 가설임을 리포트에 밝히고, 검증 방법(인터뷰·설문 질문 예시 2~3개)을 제안한다. 수치(비율 등)를 지어내서 실제 통계처럼 제시하지 않는다.
- **분량**: 리포트는 페르소나당 한 화면 안팎(대략 15~20줄)으로, 전체 2~3 페이지를 넘기지 않는다. 지역·회사 같은 배경은 현실적으로 구체화하되 실제 기업명은 쓰지 않는다.
- 사용자가 쓴 언어로 작성한다 (한국어 입력이면 한국어).

## 출력 형식

기본 산출물은 두 가지다. 파일로 저장하고 경로를 알려준다.

1. `persona-report.md` — 전체 분석 리포트
2. `persona-cards.html` — 페르소나 요약 카드 (`assets/persona-cards-template.html`의 스타일을 따라 만든다. 템플릿의 카드 블록을 **대표 페르소나 3개**만큼 복제해 내용을 채운다. 나머지 2개는 카드 아래 "그 밖의 후보" 한 줄 목록으로 둔다.)

### 마크다운 리포트 구조

```markdown
# [프로젝트명] 페르소나 분석

## 1. 프로젝트 요약
(2~3문장) + **가정한 사항** 목록

## 2. 페르소나 후보 5개 한눈에 보기
| 구분 | 페르소나 | 한 줄 별명 | 핵심 목표 | 적합도 |
|---|---|---|---|---|
(구분: 대표 / 후보)

**대표 3개 선정 이유**: ...
**제외한 2개**: 어떤 대표에 가깝거나 왜 제외했는지 한 줄씩

## 3. 대표 페르소나 상세 (3개)
### 3-1. 이름 — 별명
(템플릿 항목들)
### 3-2. ...
### 3-3. ...

## 4. 교차 분석
- 공통 니즈 / 갈리는 지점
- 우선순위 (누구를 먼저 공략할지, 이유)
- 기능·메시지 시사점

## 5. 검증 제안
(실제 인터뷰·설문에서 확인할 질문 예시, 이 페르소나가 틀릴 수 있는 지점)
```

HTML 카드는 대표 3개의 핵심(별명, 인용구, 목표, 페인포인트, 적합도, 시사점)만 담아(아바타 글자는 성이 아니라 이름 글자 1자, 예: 박민준 → "민", 김서연 → "서". B2B·양면 시장이면 역할 태그를 모든 카드에 붙인다. 프로젝트명이 가칭이면 제목에 "(가칭)"을 붙인다) 한눈에 훑게 한다. 상세 서술은 마크다운에 둔다. 두 산출물의 내용은 서로 모순되면 안 된다.

## 마무리

대화 응답에는 전체 리포트를 반복하지 말고, 대표 3개 한 줄씩 + 제외한 2개 이름 + 파일 위치 + 가장 큰 가정 1~2개를 알려준다. 그리고 수정 방향(더 세분화, 특정 지역/연령 추가, 안티 페르소나 추가 등)을 제안한다.
