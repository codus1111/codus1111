## 0. 아이디어 — 어디서 왔나 (구조화: 상황 정의)

- **경험:** 패스트푸드 매장 2년 7개월. 판매 종료나 품절 메뉴가 키오스크에 그대로 남아 주문이 들어오고, 손님에게 직접 사과하고 환불하던 일이 반복됐다.
- **이전 프로젝트와 연결:** 같은 문제를 데이터로 풀어 본 "멀티채널 메뉴 정합성 점검" (오류 15건 중 9건이 *변경 사항 반영 누락*에서 생김).
- **질문:** 이 "반영 누락"의 긴장감을 *게임의 재미*로 바꿀 수 있을까?
- **참고한 재미 (내가 즐긴 게임):** 1010!, 블록블라스트, 무한의 계단, 템플런처럼 *짧은 한 판과 한 손 탭*, 쿠키런 오븐브레이크와 서브웨이서퍼처럼 *콤보와 최고 기록 갱신*.

## 1. 문제·목표 정의 (구조화)

| 항목 | 정의 |
|---|---|
| 핵심 재미 | 주문을 빠르게 맞히는 콤보 + "품절 알림"이 끼어들 때의 우선순위 판단 |
| 긴장 요소 | 품절 메뉴를 키오스크에서 늦게 끄면 → 품절 주문이 쌓이고 → 클레임 |
| 한 판 | 60초, 기회 3번 |
| 끝나고 보여 줄 것 | 점수 외에 **품절 → OFF까지 걸린 평균 시간**, 품절 주문 건수 (실제 운영 지표처럼) |

## 2. 작게 쪼개기 (구조화)

1. 손님 대기열 + 인내심 게이지
2. 주방 탭 → 쟁반 → 서빙 판정 + 콤보 점수
3. 품절·재입고 이벤트 + 키오스크 ON/OFF (재고와 노출이 안 맞으면 깜빡임)
4. 품절 안내 버튼 (클레임은 막지만 콤보는 끊김)
5. 결과 리포트 + 최고 기록 저장

| ✍️ 나 | 아이디어와 경험 연결, 핵심 재미 정의, 직접 플레이 후 고칠 방향 판단, 최종 수치 결정 |

### v2 — 2026-11-23 · "햄부기 러시"
- **내 판단 (v1을 해 보고):**
  - "너무 간단하다. 그냥 서빙만 하는 게임이다" → **배달 주문 추가.** 매장과 배달을 동시에 처리해야 하는 실제 피크타임처럼 만들기.
  - 이모지 UI는 밋밋하다 → **도트(픽셀) 컨셉**으로. 알바생, 손님, 배달 라이더를 직접 그린 캐릭터로 넣기.
  - "햄부기"는 알바 경험에서 차용한 컨셉이라는 걸 제목과 시작 화면에 드러내기.
  - 주문표를 골라야만(빨간 활성화) 서빙되는 건 답답하다 → **되는 대로 서빙.** 쟁반과 맞는 주문(매장 맨 앞 손님 또는 배달)으로 자동 전달.
- **AI가 한 것:** 도트 스프라이트(알바생, 손님 랜덤 외형, 라이더, 스쿠터, 메뉴 6종)를 코드로 그림. 매장 장면(메뉴판에 품절 X 표시, 배달 픽업 창구, 카운터, 걷기 애니메이션) 구현. 배달 주문과 라이더, 채널 2개(키오스크, 배달앱) 노출 관리, 자동 매칭 서빙 구현.
- **결과:** 품절이 나면 키오스크와 배달앱을 **둘 다** 꺼야 하는 구조. 이전 "멀티채널 메뉴 정합성" 프로젝트의 문제의식(변경 사항이 채널마다 따로 반영돼서 생기는 오류)이 게임 규칙이 됨. 결과 화면에 채널별 "품절 → OFF 반영 시간"이 나옴.

### v3 — 2026-11-23 · 리텐션과 밸런스

- **AI가 한 것:**

  - 클레임 기준을 시작 화면, 상단 ♥, 조작부 안내, 종료 화면(이탈 N건 · 배달 지연 N건) 네 곳에 표시
