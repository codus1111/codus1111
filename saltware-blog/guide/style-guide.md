# 스타일 가이드: 솔트웨어 기업 블로그

이 문서는 솔트웨어 블로그 글의 말투와 구조를 정한다.
베스핀글로벌 블로그의 글 구조를 참고했지만, 문장과 표현은 가져오지 않는다.

## 1. 독자

- 고객사 실무자와 팀장: IT팀, 데이터팀, 기획팀, 보안 담당자
- 기술 용어를 들어는 봤지만 정확히 설명하기는 어려운 사람
- 목표: 글을 다 읽고 "우리 회사도 해 볼 수 있겠다"고 느끼게 만든다

## 2. 시리즈 두 개

글을 쓰기 전에 둘 중 하나를 고른다. 사용자가 정하지 않으면 주제를 보고 고른다.

| | 데이터 한 스푼 | [데이터 노트] |
|---|---|---|
| 언제 | 용어나 개념 하나를 설명할 때 | 기업이 부딪히는 문제 하나를 주장으로 풀 때 |
| 말투 | 해요체 ("~요", "~죠") | 습니다체에 "~죠", "~인데요"를 가끔 섞음 |
| 제목 | 질문형이나 말 거는 문장 + 이모지 1개 | `[데이터 노트] 주제 · 짧은 부제` (이모지 없음) |
| 시작 | "안녕하세요, 솔트웨어 블로그 '데이터 한 스푼'입니다." + 오늘 고른 단어 | 누구나 겪어 본 장면 하나로 시작 |
| 소제목 | 말 거는 질문이나 짧은 감상 ("그럼 뭐가 다른데요?") | 짧은 주장 문장. 마지막 소제목은 "정리하며" |
| 끝 | "오늘의 한 스푼" 소제목 + 핵심 한 줄 굵게 + 다음 글 예고 | 요약 + 다음 회차 예고 |
| 길이 | 2,500~4,000자 | 2,000~3,000자 |

### 고객 사례 (세 번째 시리즈)
- 언제: `guide/saltware-knowledge.md`에 실린 실제 고객 사례를 풀어 쓸 때만. 사례를 지어내지 않는다
- 제목: `[고객 사례] 고객사 · 겪던 문제를 한 줄로`
- 구조: 이런 회사였어요 → 이런 문제가 있었어요 → 이렇게 바꿨어요 → 바뀐 점 → 비슷한 회사라면
- 말투: 습니다체. 고객사 입장에서 담담하게
- 숫자: 원문에 숫자가 없으면 "얼마나 줄었는지는 공개되지 않았다"고 그대로 쓴다
- 끝에 원문 사례 링크를 꼭 단다

## 3. 글 구조 (공통)

1. 위쪽 정보 줄: `시리즈명 · 팀명 [이름] · 날짜`
2. 제목
3. 도입 (2~3문단): 독자가 실제로 겪는 장면이나 비유로 연다
4. 본문 소제목 3~5개
5. 자사 이야기 박스 (한 번만, 뒤쪽에): 제목은 "솔트웨어는 이렇게 하고 있어요" 또는 "솔트웨어가 고객사와 일하며 보는 것"
6. 마무리
7. 해시태그 5개
8. 문의하기 · 뉴스레터 구독 안내 한 줄

## 4. 문장 규칙

- 한 문단은 2~4문장. 한 문장짜리 문단도 괜찮다
- 비유는 사무실, 집, 창고, 사원증처럼 회사원이 매일 보는 물건으로 든다
- 굵은 글씨는 한 소제목에 한 번 이하
- 목록은 3개 이하일 때만 쓴다. 나머지는 문장으로 풀어 쓴다
- 영어 용어는 처음 나올 때 한글 설명을 붙인다. 예: RAG(AI가 사내 문서를 찾아 읽는 방식)

## 5. AI가 쓴 티를 없애는 규칙 (반드시 지킬 것)

다음 표현은 쓰지 않는다.

- "~에 대해 알아보겠습니다", "~를 살펴보겠습니다"
- "결론적으로", "요약하자면", "다양한", "효율적인", "혁신적인", "획기적인"
- "단순히 A가 아니라 B입니다" 같은 뒤집기 문장을 한 글에 두 번 이상
- 같은 문장 끝맺음을 세 번 연속 쓰기 ("~예요. ~예요. ~예요.")
- 문장 중간의 줄표(—)
- 본문 속 이모지 (제목의 이모지 1개만 허용)
- 화살표(→)로 문장 잇기

## 6. 자사 이야기 규칙

- 자사 제품 이름은 글 뒤쪽 30% 안에서만 꺼낸다
- 효과를 부풀리지 않는다. 확인된 사실만 쓴다
- 실제 사례나 숫자가 없으면 `[확인 필요: ○○]`라고 표시하고 비워 둔다. 지어내지 않는다

## 7. 솔트웨어 기본 정보 (글에 써도 되는 사실)

- 2003년 설립, 2022년 코스닥 상장
- 슬로건: Connect Any Data. Understand with AI. Act with Agents.
- AI 데이터 플랫폼: Sapie-ADP, Sapie-Agent
- 데이터: Databricks, Starburst, Sapie-Lake
- 클라우드: AWS, Red Hat, FitCloud(AWS 요금 통합·운영 관리)
- 보안: SailPoint(계정·권한 관리), Sapie-Guardian(외부 AI로 보내기 전 민감정보 검사)
- AWS Competency 4개 분야, 2026년 9월 AWS MSP 프로그램 인증
- 2008년 이후 누적 고객사 1,900곳 이상, 2021~2026년 AWS 세미나 71회
