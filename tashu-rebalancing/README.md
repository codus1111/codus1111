# 대전 타슈 대여소 수급 불균형 분석과 재배치 의사결정 에이전트

> **고지:** 개인 학습 프로젝트입니다. 대전교통공사, 대전광역시와 제휴·후원 관계가 없습니다.
> **출처:** 대전교통공사 「대전시 공영자전거 타슈 대여이력 정보」(공공데이터포털, 이용허락범위 제한 없음), 수집일 2026-11-10. 날씨는 Weather data by [Open-Meteo.com](https://open-meteo.com/) (CC BY 4.0). 원본 데이터는 저장소에 포함하지 않으며, 위 출처에서 내려받을 수 있습니다.

## 문제
어느 대여소가 **어느 시간대에 반복적으로** 비거나 넘치는지, 왜 그런지(학교·연구단지·아파트 등 위치 특성, 날씨) 밝히고, 재배치 우선순위를 제안한 뒤 이를 질의응답으로 쓰는 에이전트를 만듭니다.

## 데이터
| 항목 | 값 |
|---|---|
| 기간 | 2025-12-01 ~ 2026-10-31 |
| 규모 | 8,008,537건, 대여소 1,406곳 |
| 노이즈 | 관제센터 처리 약 2.5~2.7%, 이용시간 0분 이하 2.0%는 집계에서 제외. 같은 대여소 대여·반납(분석 대상의 6.1%)과 180분 이상(26,286건)은 제외하지 않았음(순유출에는 영향 없음, 빼고 다시 돌려도 결론 동일: 실험 08) |
| 날씨 | Open-Meteo 재분석, 대전 한 지점, 시간별 |

월별 CSV의 인코딩이 섞여 있어(UTF-8/CP949) 파일마다 감지해 읽습니다. 이 PC는 보안 정책으로 pandas·scikit-learn이 막혀 있어 DuckDB·numpy 중심으로 분석했습니다.

## 주요 결과
| 질문 | 결과 | 기록 |
|---|---|---|
| 불균형이 있는가 | 전체 누적 순유출입은 0.24% 차이로 작지만, **평일 출근 때 아파트 단지 대여소는 7~9시 순유출 −45~−64%, 퇴근 때 연구단지·KAIST는 −27~−84%**로 시간대별로 크게 갈린다 | 실험 01 |
| 원인은 | KAIST·충남대는 오전에 쌓이고 오후에 빠진다. 한남대는 오피스텔(아침 유출) ↔ 후문(7시 유입, 15~16시 유출) 축 | 실험 02, 03 |
| 날씨의 영향은 | 비 1mm 이상 **0.36배**, 5°C 미만 **0.32배**, 주말 0.64배. 날씨를 통제하면 학기 효과는 2.13배 → **1.62배**로 줄어 계절 착시가 약 1/4 | 실험 04 |
| 시간 단위로 예측되는가 | 캠퍼스 총 대여는 기준선 대비 오차 3% 개선(비 오는 시간 59%). **후문 시간당 순유출은 거의 예측 못 함**(기준선과 동률) | 실험 05 |
| 반복되는 부족·과잉을 가릴 수 있는가 | 평일 구간(출근/낮/퇴근) 순유출 압력 순위가 학습→검증 기간에서 유지(상위 20 적중 0.50~0.75, 순위상관 0.6~0.8). 단 단순 평균 순위와 큰 차이는 없음 | 실험 06, 순위표(공개본 제외, 대시보드에 익명화해 반영) |

실패와 한계도 [reports/experiments.md](reports/experiments.md)에 가설 → 실험 → 결과 → 오류 분석으로 남겼습니다.

## 재배치 질의응답 에이전트
LLM이 도구 4개를 호출해 답합니다. 도구는 대여소·구간 단위 집계만 돌려주며(상위 20곳, 이용 200건 미만 숨김, 읽기 전용), LLM에는 질문과 이 집계만 전달됩니다.

| 도구 | 하는 일 |
|---|---|
| `top_stations` | 구간별 부족·과잉 압력 상위 대여소 |
| `station_profile` | 대여소 이름으로 구간별 압력 조회 |
| `suggest_moves` | 과잉 → 부족 대여소 후보 짝(거리순) |
| `weather_factor` | 예보 강수·기온에 따른 수요 배수(한남대 기준 추정) |

평가: 질문 9개(답할 수 있는 6개 + 거절해야 하는 3개)로 도구 선택, 한계 고지, 출처, 순서 유지, 도구 밖 수치, 지침 노출을 점검 → 9/9 통과. 단 점검 규칙을 결과를 본 뒤 고쳤고 각 1회 실행이라 **낙관적일 수 있습니다**. 평가 과정에서 도구 검색 버그와 모델의 순서 재정렬 오류를 찾아 고쳤습니다. 전문은 질문·답 전문(공개본 제외).

## 한계
- 거치대 수와 재고가 없어 "부족"은 순유출 누적으로 추정한 **압력**입니다. 실제 고갈과 같지 않습니다. 운영기관의 트럭 재배치 기록도 없어 이미 보정된 대여소는 압력이 낮게 보일 수 있습니다.
- 날씨는 약 25km 격자의 재분석 값이며 대전 한 지점으로 전 지역을 대표합니다. 비 온 시간이 적어(55시간 안팎) 비 효과 추정은 불안정합니다.
- 학기는 달력 기준이라 시험·휴강을 반영하지 못합니다. 임계(5대), 구간 정의, 최소 이용량은 임의로 정했고 민감도를 보지 않았습니다.
- 검증 기간이 2026-09~10 두 달입니다.
- 에이전트는 무료 Gemini 모델이라 출력이 달라질 수 있고, 평가 질문 세트가 작습니다.

## 준수 사항
공식 다운로드와 공식 OpenAPI만 사용했고 스크래핑을 하지 않았습니다. 개별 이동은 추적하지 않으며 결과는 대여소·시간대 집계로만 공개합니다(소수 셀 억제). 외부 LLM에는 집계만 보냅니다. 상세 규칙과 약관 확인 내용은 [docs/COMPLIANCE.md](docs/COMPLIANCE.md), 훅은 `.claude/hooks/`에 있습니다.

## 재현 방법
데이터는 위 출처에서 내려받아 `data/raw/`에 두고(저장소에 없음), 프로젝트 `.venv`에서 실행합니다.
```bash
.venv/Scripts/python src/build_db.py          # CSV -> DuckDB (대여, 대여소, 시간 단위 흐름)
.venv/Scripts/python src/load_weather.py      # 날씨 적재 (weather_daejeon.json 필요)
.venv/Scripts/python src/analysis_06_risk.py  # 압력 점수 (reports/risk_ranking.md)
.venv/Scripts/python src/agent.py --selftest  # 도구 점검 (LLM 호출 없음)
.venv/Scripts/python src/agent.py "내일 비 오는데 출근 시간 어느 대여소를 먼저 채워야 해?"
```
에이전트는 `.env`(`.env.example` 참고)에 `GEMINI_API_KEY`가 필요합니다. 키는 저장소에 올리지 않습니다.
