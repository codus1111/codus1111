# AI 버튼 시험 기록 (P15, 2026-11-26)

버튼(`agent-dashboard/index.html`의 "AI 보내기 전 확인")이 만든 확인 글을 그대로, 맥락 없는 새 서브에이전트(Claude Sonnet, 도구 사용 안 함)에 예시마다 따로 보냈다. 예시 글은 시험용으로 지어낸 글이다(수치·자전거번호 모두 가상).

## 결과
| 예시 | 기대 | 1회차 실제 | 고친 횟수 | 2회차 실제 | 일치 |
|---|---|---|---|---|---|
| A 규칙을 지킨 글 | 보내도 돼요 | 보류(사람 확인) | 1 (기준 ① 문구, 판단 불가 규칙) | 보내도 돼요 | 2회차 일치 |
| B 출처 없음·과장·"3건" | 고쳐서 다시 | 고쳐서 다시 | 0 | — | 일치 |
| C 자전거번호·분 단위 이동 | 보류(사람 확인) | 보류(사람 확인) | 0 | — | 일치 |

최종: 3개 중 3개 기대와 같음(A는 한 번 고친 뒤).

## 화면 안 점검 (서브에이전트 전에)
- 빈 입력 → "확인할 글을 먼저 붙여 넣으세요." 결과 숨김. 기대대로.
- `API_KEY=abc` 포함 → 만들지 않음, 결과 숨김, 경고에 종류만 표시(값은 표시 안 함). 기대대로.
- 예시 A·B·C 본문은 키 점검에 걸리지 않음.
- 기존 탭 5개 전환, 콘솔 오류 없음.
- 클립보드: 처음엔 미리보기 브라우저가 쓰기 권한을 막아 실패 → `execCommand('copy')` 대체 경로를 더한 뒤 실제 클릭에서 "복사했습니다" 확인. 사용자 크롬에서는 아직 안 눌러 봄.

## 1회차 A가 틀린 이유와 고친 것
- 서브에이전트가 ①에서 "날씨를 썼으면 Open-Meteo"라는 조건 때문에 "날씨 사용 여부를 알 수 없음 → 판단 불가"로 답했고, 판정 규칙상 판단 불가가 있으면 보류가 됐다. **설계서(기준 문구)가 틀린 곳.**
- 고친 것: ① "날씨 출처는 글에 날씨 이야기가 있을 때만 필요". 답 양식에 "판단 불가는 글에 없는 정보가 있어야만 결론이 바뀔 때만, 해당 내용이 없는 조건은 ✓".
- 1회차는 ⑥에서도 "쌓이는 곳은 연구단지·업무지구·캠퍼스 주변이었다"에 수치가 없다고 지적했다. 2회차는 같은 글에 ⑥ ✓를 줬다. 지적 자체는 일리가 있다.

## 사람이 확인할 것
- 2회차 A 답은 처음에 ①·④를 "고칠 것"이라 적었다가 스스로 ✓로 정정한 뒤 최종 답을 다시 썼다. 판정은 맞았지만 **답 양식이 흔들린다** → 마지막 "판정:" 줄만 믿지 말고 기준별 줄을 읽을 것.
- 같은 글이라도 회차마다 ⑥ 판단이 달랐다(1회차 지적, 2회차 ✓). 예시당 1회씩만 돌려서 안정성은 모른다.
- B·C는 고치기 전 기준 문구로 돌렸다. ① 변경은 B(출처 없음)·C(출처 있음, 날씨 없음)의 결론에 영향이 없을 것으로 보지만 다시 돌리지는 않았다.
- 버튼 글은 사용자가 Claude 새 채팅에 붙여 넣는다(외부 전송). 화면 안 키 점검은 정규식이라 자전거번호·원본 행은 못 거른다 → 붙여 넣기 전에 사람이 본다.
