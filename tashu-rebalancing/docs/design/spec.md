# 설계서: "공개 전 확인" AI 버튼 (P13-2, 2026-11-26)

## 한 줄
README·보고서·포트폴리오에 올릴 글을 붙여 넣고 누르면, 프로젝트 규칙 여섯 개로 확인해 달라는 요청 글을 만들어 복사해 주는 버튼.

## 누가, 언제
- **누가:** 이 프로젝트를 혼자 진행하는 나(분석·작성자).
- **언제:** 분석 결과를 README, `reports/`, 블로그·포트폴리오, 발표 자료에 **공개하기 직전**.
- **왜:** 지금은 출처 표기, 비제휴 고지, 소수 셀 억제를 눈으로 확인한다. 빠뜨리기 쉽고 매번 기준이 달라진다.

## 입력 → 출력
- **입력:** 공개할 글(한국어, 보통 1~20문단). 붙여 넣기만 한다.
- **버튼이 만드는 것:** 기준 여섯 개와 답 양식이 들어간 확인 요청 글. 화면에 보여 주고 클립보드에 복사한다.
- **붙여 넣는 곳:** Claude 새 채팅(사람이 직접 붙여 넣음).
- **AI 답의 모양:** 기준마다 `✓` 또는 `고칠 것: …(어느 문장, 어떻게)` 또는 `판단 불가: 이유`(글에 없는 정보가 있어야만 결론이 바뀔 때만), 마지막 줄에 판정 셋 중 하나.
  - **보내도 돼요**: 여섯 개 모두 ✓
  - **고쳐서 다시**: ③ 외의 기준에 고칠 것이 있음
  - **보류(사람 확인)**: ③(개인·비밀 정보)에 걸림, 또는 AI가 판단할 수 없다고 한 기준이 있음

## 기준 여섯 개
| # | 기준 | ✓가 되려면 |
|---|---|---|
| ① | 출처 표기 | 데이터 출처(대전교통공사 타슈 대여이력, 공공데이터포털)가 글에 있다. 날씨 출처(Open-Meteo, CC BY 4.0)는 글에 날씨 이야기가 있을 때만 필요하다 (P15 1회차 뒤 고침) |
| ② | 비제휴 고지 | "개인 학습 프로젝트이며 대전교통공사·대전광역시와 무관" 취지의 문장이 있다 |
| ③ | 개인·비밀 정보 없음 | 자전거번호, 개별 이용자의 이동 경로(어디서 몇 시 몇 분에 어디로), 좌표 단위 위치, API 키·토큰이 없다. 결과는 대여소·시간대 단위다 |
| ④ | 소수 셀 억제 | 10건 미만의 건수를 그대로 적지 않았다("10건 미만"으로 합치거나 숨김). 시각은 분이 아니라 시간대 단위다 |
| ⑤ | 비방·과장 없음 | 운영기관을 탓하거나("방치", "실패"), 데이터가 말하지 않는 것을 단정하지 않았다 |
| ⑥ | 근거와 확실성 | 수치에 기간·단위가 있고, 추정·가설은 [추론]/[가설]처럼 확인된 사실과 구분된다 |

## 바꿀 파일

- `agent-dashboard/README.md`: 쓰는 법 표에 한 줄.
- 시험 기록: `docs/design/button_test_1126.md`.

## 위험
- 붙여 넣은 글에 행 단위 원본이나 키가 섞이면 외부 LLM으로 나간다(규칙 10). → 화면 안 점검 + 패널 안내 문구. 점검은 완벽하지 않으므로 최종 책임은 사람.
- 붙여 넣은 글을 innerHTML로 넣으면 스크립트 주입. → value/textContent만 쓴다.
- 기존 끌어 놓기 처리기가 입력 칸 끌어 놓기를 막는다. → 입력 칸에서만 따로 처리.
- `file://`에서 클립보드 실패. → 대체 경로.

## 성공 기준
- 글을 붙여 넣고 "확인 글 만들기"를 누르면 기준 여섯 개와 판정 셋이 들어간 글이 보이고 클립보드에 복사된다.
- `API_KEY=`가 들어간 글을 넣으면 복사되지 않고 이유가 보인다.
- 기존 탭·재생·실행 기록 열기·파일 끌어 놓기가 전과 같이 동작한다(콘솔 오류 없음).
- 정답 아는 예시 3개를 버튼 글로 새 눈(서브에이전트)에 보냈을 때 판정이 기대와 같다.

## 하지 않는 것
- 화면 안에서 AI를 직접 부르기(API 키를 화면에 넣지 않는다).
- ChatGPT 등 아직 약관 확인을 안 한 외부 서비스 안내.
- 글을 자동으로 고치기. 고치는 건 사람이 한다.
- 데이터 파일 읽기, 서버(`serve.py`) 변경, `reports/dashboard.html` 변경.
